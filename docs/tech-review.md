## 3. AI 해설 출력 형식 (안)

```json
{
  "facts": ["객관적 시각 정보 (인물, 사물, 색채, 구도)"],
  "interpretations": ["분위기와 가능한 감정적 해석"],
  "regions": [{ "label": "붉은 꽃", "bbox": [0.05, 0.70, 0.20, 0.25], "color": "붉은색" }],
  "mood_keywords": ["고요", "쓸쓸함"]
}
```

- `facts`와 `interpretations`를 나눠서 "사실과 해석을 구분한 해설"을 구현합니다.
- `regions`로 위치 안내("왼쪽 아래에 붉은 꽃")와 영역 터치 설명을 구현합니다. bbox는 이미지 크기 대비 비율(0~1)입니다.
- `mood_keywords`는 배경음악 추천에 씁니다.
- DB의 작가, 제목, 배경 정보를 프롬프트에 넣어 **근거 기반으로 생성**합니다. 미등록 작품은 작가나 제목을 추측하지 않도록 합니다.

## 5. 구현 단계

### P0: 데모 핵심 (반드시 동작해야 함)
1. **카탈로그 구축**: 공공 도메인 작품 300~1000점 (Met Open Access, 공공누리 등). 메타데이터, 고화질 원본, CLIP 임베딩을 준비합니다.
2. **해설 사전 생성**: 3장 JSON 형식으로 생성한 뒤 데모 대상 작품을 우선 검수합니다.
3. **시각 프로필 생성**과 기기 저장. 테스트 방식은 보류 항목 4번입니다.
4. **작품 사진·명패 촬영 → 인식**: CLIP 유사도 검색과 명패 텍스트 퍼지 매칭. 촬영 품질은 규칙 기반으로 검사합니다 (흐림: 라플라시안 분산, 반사: 하이라이트 비율).
5. **DB 원본 표시 + 앱 실시간 보정** (규칙 기반). 원본 전환, 강도 슬라이더, 핀치 줌을 포함합니다. 이 규칙 기반 보정은 6장 학습 모델의 **비교 기준선**이 됩니다.
6. **해설 재생** (expo-speech, 속도 조절, 반복)

### P1: 차별화
7. **학습한 보정 모델 연동** (6.1). 규칙 기반 보정을 대체하거나 옵션으로 둡니다.
8. **학습한 인식 어댑터 연동** (6.2)
9. **영역 터치 설명**과 색 이름 안내 (`regions` 활용)
10. **미등록 작품**: Gemini 실시간 분석과 촬영본 보정
11. 인식이 애매할 때 후보 선택 화면 (보류 항목 5번 결과에 따름)

### P2: 여유가 있을 때
12. 배경음악: `mood_keywords`와 음원 매핑 테이블로 재생. 해설 중 덕킹을 포함합니다.
13. 관람 기록과 피드백 → 보정값 반영
14. LightGlue 재순위화 (CPU에서 느리므로 어댑터 성능을 보고 결정)
15. 촬영 품질 분류기 (규칙 기반 검사를 학습 모델로 대체)

### 범위에서 제외 (향후 계획)
- PaddleOCR (Gemini로 대체)
- 실제 촬영 데이터 기반 대규모 파인튜닝
- 사용자 피드백 기반 선호 학습 모델 (다수 사용자 데이터가 필요)

## 6. AI 학습 계획 (임의 작성 · AI 담당자 검토 필요)

> 📝 **AI 담당자 검토 요청**
> 이 장은 공모전 심사기준의 "AI 모델 학습" 항목에 대응하려고 BE 담당이 **임의로 작성한 안**입니다. 모델 구조, 손실 함수, 데이터, 일정의 실현 가능성을 AI 담당자가 검토한 뒤 **적절한 방향으로 수정**해 주세요. 더 나은 대안이 있으면 이 장을 통째로 바꿔도 됩니다.
> 공모전 심사기준 원문(학습 항목의 정확한 문구)을 확인해 이 장 맨 위에 붙여 주시면 방향을 정하는 데 도움이 됩니다.

### 방향
학습 요소를 서비스의 핵심 가치인 **개인 맞춤 보정**에 둡니다. 작품 인식 쪽은 위험이 낮은 보조 학습 요소로 둡니다.

### 6.1 주 학습: 작품·사용자 맞춤 색 보정 모델

**목표**: 고정 알고리즘(달토나이제이션)은 모든 작품에 같은 변환을 적용합니다. 이 모델은 **작품별·사용자별로 최적의 색 변환을 예측**합니다.

```
입력: 작품 이미지(축소본) + 시각 프로필(색각 유형, 심도, 보정 강도 선호)
  ▼
작은 CNN (서버에서 CPU로 추론)
  ▼
출력: 색 변환 행렬(3×3) + 편향 + 밝기·대비 파라미터 (숫자 약 15개)
  ▼
앱(Skia)이 이 파라미터로 실시간 보정 (1-3과 호환)
```

- **자기지도 학습 (라벨 불필요)**: 색각이상 시뮬레이션(Machado 2009, 선형 행렬이라 미분 가능)을 손실 함수 안에 넣습니다.
  - `L_구별력`: 정상 시각에서 구별되던 색 쌍이 **변환 후 색각이상 시뮬레이션에서도 구별되도록** 합니다.
  - `L_원본충실도`: 원본에서 너무 멀어지지 않도록 합니다. 기획 의도인 "원본 유지"를 수식으로 표현한 항입니다.
  - 두 항의 가중치를 사용자의 보정 강도 선호로 조건화합니다.
- **데이터**: WikiArt와 공개 소장품 회화 수천 점
- **학습 환경**: Colab 또는 Kaggle 무료 GPU. 추론은 CPU로 합니다.
- **범위**: 1차는 색각이상 보정에 한정합니다. 대비와 밝기는 규칙 기반을 유지합니다 (객관적인 손실 함수를 정의하기 어렵기 때문).
- **기준선 비교**: 보정 없음, 기존 달토나이제이션, 이미지별 최적화 방식(속도 비교용)
- **평가 지표**: 시뮬레이션상 색 구별률(CIEDE2000), 원본과의 차이, 추론 시간. 가능하다면 색각이상 당사자의 A/B 선호 평가도 진행합니다.
- **예상 질문 대비**: "이미지마다 최적화하면 되지 않나?" → 학습 모델은 즉시 예측하고(실시간) 처음 보는 작품에도 일반화된다는 점을, 이미지별 최적화 대비 속도 비교로 보여줍니다.
- **보류 항목 4번(달토나이제이션)과 직접 연결**됩니다.

### 6.2 보조 학습: CLIP 인식 어댑터 (대조학습)

- CLIP ViT-B/32는 고정하고, 그 위의 작은 MLP 어댑터만 InfoNCE 손실로 학습합니다. CPU로 수 분이면 됩니다. 효과가 작으면 Colab에서 마지막 블록까지 미세조정합니다.
- **데이터**: 카탈로그 원본에 미술관 촬영 환경을 흉내 낸 **합성 증강**을 적용합니다 (원근 왜곡, 크롭, 흐림, 반사광, 조명 색온도, JPEG 압축, 액자·벽 배경). 작품당 약 100장입니다.
- **테스트셋은 실제 촬영본만** 씁니다. 모니터나 인쇄물을 찍은 사진도 가능하며, 학습에는 섞지 않습니다.
- 카탈로그가 작으면(50점 등) CLIP만으로도 정확도가 거의 100%가 나와 학습 효과를 보여줄 수 없습니다. 그래서 **300점 이상**으로 하고 같은 작가의 비슷한 작품을 포함시킵니다.
